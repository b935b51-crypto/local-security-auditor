# Native secret scanner — Phase 2

## Scope and entry point

`SecretScanner.scan_discovery(session, discovery)` consumes only `FileArtifact` objects admitted by Phase 1, uses the canonical discovery root, and propagates incomplete discovery coverage. `scan(session, artifacts)` implements the synchronous `Scanner` protocol for an orchestrator that already selected admitted artifacts. Neither entry traverses the tree. `discovery.content.read_admitted_artifact` rechecks relative components, containment, reparse status, regular-file type, device/file identity, size, and modification time before and after a bounded read. These checks reduce but cannot eliminate concurrent Windows filesystem races.

Only Phase 1 `TEXT` artifacts with a known encoding are eligible. Archives, binaries, executables, unknown/undecodable content, and Phase 1 skips are not secret-scanned. Source, scripts, env, config, manifests, lockfiles, CI, documentation, key-material-like text, and certificate-like text (which may contain a private key) can be scanned. Public certificates produce no finding. Discovery controls vendor/build excludes. The scanner does not inspect Git history, archives, process environment, credential stores, or live services.

## Detection and precision

Evaluation order is private-key marker, provider shape, credential-bearing connection URL, JWT structure, assignment, then contextual entropy. Stable rule metadata is in `scanners/secrets/rules.py`. Provider subsets cover GitHub `gh[pousr]_`, AWS `AKIA`/`ASIA` IDs, Stripe `sk_live_`/`sk_test_`, Slack `xox…-`, and GitLab `glpat-`. Shape is not proof of validity. An AWS ID alone is LOW severity/MEDIUM confidence; a nearby strong `AWS_SECRET_ACCESS_KEY` assignment raises it to HIGH/HIGH.

Assignment detection is line based for common Python, JS, JSON, YAML, TOML, env, and INI syntax. It requires a value with sufficient length/diversity; in non-JS/TS text, a call expression may otherwise look like a hardcoded value to this textual rule. Entropy strengthens assessment but never acts alone. JWT detection checks bounded base64url header/payload JSON object shape without signature verification. Credential URL detection covers postgres/postgresql, MySQL, MongoDB, and Redis user:password forms. Public certificates and SSH public keys are excluded. A private-key BEGIN marker produces one finding; its body never enters candidate metadata.

Exact placeholders (`YOUR_API_KEY`, `CHANGE_ME`, `FAKE_TOKEN`, repeated `x`/`0`, etc.), empty/null values, standard UUIDs, environment references, and secret-manager references are suppressed. Hash/checksum/digest/integrity/commit/etag context gates generic rules but does not silence a provider-specific shape. Documentation, examples, and tests remain eligible; documentation wording lowers generic-assignment confidence. Synthetic provider-shaped values can still be reported. This rule set favors precision over exhaustive coverage.

Golden-case precision: for a Python file no larger than 128 KiB, the generic assignment rule suppresses a direct `secrets.token_urlsafe`, `secrets.token_hex`, or `secrets.token_bytes` call only when bounded AST parsing shows an earlier top-level `import secrets` and no lexical rebinding of `secrets`. A quoted string containing generator-looking text remains eligible. A parse failure, larger file, unfamiliar helper, or shadowed name keeps the ordinary rule eligible. `secrets.choice` and `SystemRandom` are not allowlisted because one call does not establish the strength or construction of the final credential. In test-named paths, a small explicit set of lowercase, digit-free synthetic literals (such as `fake-test-password` or `do-not-echo`) is suppressed only for the generic assignment rule. Tests are still scanned, and provider-specific, private-key, JWT, and URL rules retain their precedence and severity. Both suppressions are conservative static heuristics, not proof that runtime output or a test fixture is safe.

## JS/TS source awareness (1.0.3 candidate hardening)

For `.js`, `.jsx`, `.ts`, and `.tsx` families, generic assignment and contextual entropy now consider bounded **source literal material**, not an identifier, property name, function call, or member-access expression merely rendered as text. A small lexical reader identifies quoted strings, static portions of template literals, and bounded nested quoted fallbacks inside `${...}`; the dynamic expression text itself is not literal material. One-line assignment continuations are handled with a bounded prefix while preserving the actual finding line and column. A hardcoded quoted credential remains eligible. Literal fallbacks after `??`, `||`, `+`, or a ternary remain eligible, including mixed environment/literal expressions. Provider-specific, private-key, JWT, and credential-URL detectors retain their independent precedence and are not suppressed by this generic-only decision.

Direct `process.env.NAME` and `process.env["NAME"]` references are recognized as environment references, including `.trim()` and `?.trim()`. A bounded function parameter declaration such as `environment: Partial<NodeJS.ProcessEnv>` is static evidence for an environment abstraction; an arbitrary object called `config` or `environment` is not trusted by name alone. This declaration does **not** prove the runtime caller supplies a trustworthy value. Unknown calls and properties are classified as runtime references, not as cryptographically secure generators and not as hardcoded source literals unless a separate eligible literal is present. This is Secret Scanner provenance for generic credential claims, not JavaScript/TypeScript source-to-sink SAST.

Test directories and `*.test.*`/`*.spec.*` JS/TS filenames provide only a context signal. A generic test literal needs a separate bounded synthetic marker (`fake`, `dummy`, `test`, `synthetic`, `example`, `placeholder`, `mock`, or `invalid` at a word/token boundary), an existing explicit test placeholder, or a narrowly recognizable private-note test-data shape before the generic credential claim is suppressed. Substrings in words such as `contest` and `attested` do not qualify. Production files with the same marker receive ordinary detection. Provider-specific shapes in tests remain reportable at their normal severity. This classification is heuristic and can misclassify unusual fixtures; it does not ignore `test/` or `tests/`.

UUIDs and hash/digest/checksum contexts retain their established generic-rule gates. A secret-named opaque literal is still evaluated even when it resembles a hash; shape alone is not a suppression rule. Generic JS/TS entropy now scans literal spans only, so a runtime property such as `previewInitialPortfolio(...).token` cannot become a high-entropy credential merely because its function name has diverse characters. Bounded large-text windows use the same literal-only generic checks. A cross-line expression entering a long-line window is marked incomplete when its context cannot be proven; it is not silently declared covered.

## Redaction and identity

Raw bytes/text exist only during bounded reading and detection. Detectors immediately construct raw-free `SecretCandidate` objects containing only rule, span, family, length, safe label, and fixed redacted preview. Python cannot guarantee memory zeroization; the design minimizes lifetime and propagation. `Finding`, `Evidence`, diagnostics, exception messages, logs, and results never intentionally contain matched values. Evidence uses `[REDACTED CREDENTIAL]`, `[REDACTED PASSWORD]`, or `[REDACTED PRIVATE KEY]` and safe structural fields. `sanitize_url_for_evidence()` discards userinfo, host, path, fragment, and query names/values, retaining an allowlisted scheme and query count. Future reporters must recheck redaction and escape target-controlled text.

The public fingerprint is SHA-256 over length-prefixed schema version, rule ID, redacted root-relative path, line/column, family, and safe label. It never hashes the secret. If a filename contains a matched value, that occurrence is replaced with `[REDACTED]` before entering `Location` or fingerprint input. A value change at the same anchor retains identity; a move changes it. Cross-file secret reuse correlation is deferred because no safe persistent HMAC-key lifecycle exists. Overlapping candidates on one line are deduplicated by detector precedence; distinct spans remain separate. Ordering is deterministic by artifact, line, column, and rule. `created_at` and elapsed-time checks are runtime dependent.

## Assessment, budgets, and completeness

Severity means potential impact if real; confidence means certainty from static evidence. HIGH/HIGH applies to private-key markers, strong provider shapes, and credentialed URLs. AWS IDs alone are LOW/MEDIUM; JWT is MEDIUM/MEDIUM; strong generic assignments usually MEDIUM/MEDIUM; weaker password assignments MEDIUM/LOW; contextual entropy LOW/LOW. Findings do not claim credentials are active or compromised.

Operator-selected `[secrets]` config has hard ceilings and cannot disable redaction or enable network validation. Defaults: 1 MiB full-buffer threshold, 4 MiB maximum Secret-scannable file size (also the unchanged hard ceiling), 64 MiB total, 16 KiB small-file line limit, 100 matches per rule per file, 100 findings per file, 1,000 findings total, and 300 seconds. A trusted explicit `max_file_bytes` below 4 MiB still acts as a per-file cap. Files above that cap are skipped, not prefix-scanned. The established `FULL_BUFFER` path still skips overlong lines and marks `PARTIAL`; the `LARGE_TEXT_BOUNDED` path scans long lines in bounded segments. Per-file limits or incomplete rule context produce `PARTIAL`; global byte/finding/time limits produce `ABORTED`; invalid discovery produces `FAILED`; fully covered eligible artifacts produce `COMPLETE`. Deadline checks are best effort between bounded read/analysis segments.

`ScannerResult.summary` counts considered/scanned/skipped artifacts, bytes, candidates, findings, placeholder and overlap suppressions, limit hits, and completeness. It also records full-buffer files, bounded large-text files/bytes, incomplete large-text files, and long-line counts. Fixed-code diagnostics contain no source or exception text: `SECRET_FILE_TOO_LARGE`, `SECRET_SCAN_BYTE_BUDGET_REACHED`, `SECRET_MATCH_LIMIT_REACHED`, `SECRET_LINE_TOO_LONG`, `SECRET_LARGE_TEXT_INCOMPLETE`, `SECRET_DECODE_UNAVAILABLE`, `SECRET_READ_FAILED`, `SECRET_RULE_ERROR`, `SECRET_SCAN_ABORTED`, `SECRET_DISCOVERY_INCOMPLETE`, `SECRET_PRIVATE_KEY_UNTERMINATED`, and `SECRET_FINGERPRINT_COLLISION`. Each code appears at most once to bound diagnostic memory. Deliberately excluded nontext files count as skipped without making coverage partial.

Hardening #5 attaches the already admitted, target-relative path to the first `SECRET_FILE_TOO_LARGE` diagnostic. The same safe path handling applies to the per-file `SECRET_LINE_TOO_LONG`, `SECRET_LARGE_TEXT_INCOMPLETE`, `SECRET_READ_FAILED`, and `SECRET_DECODE_UNAVAILABLE` diagnostics. Global or ambiguous diagnostics retain a null path. The path passes the existing credential-shaped filename redactor in the scanner and the report's path sanitizer; messages remain fixed and source-free. A diagnostic identifies the first affected artifact for its code, because codes remain deduplicated. Filename redaction is heuristic for unfamiliar credential shapes. Hardening #8 retains the 1 MiB full-buffer threshold and 4 MiB hard per-file ceiling; text logs are not excluded by default. An applicable file above the configured Secret scan maximum continues to make Secrets `PARTIAL`.

## Bounded large-text mode (Hardening #8)

Text files above 1 MiB and within the Secret and Discovery file caps use the admitted-artifact reopen with the same root, reparse, identity, size, and mtime checks as the small-file reader. It yields 64 KiB byte chunks and verifies identity after exhaustion. An incremental strict decoder handles UTF-8 characters across chunk boundaries; malformed input yields a safe relative-path diagnostic and `PARTIAL`. The scanner keeps at most a small line buffer or an approximately 12 Ki-character window with 4 Ki-character overlap, not an entire 485 KiB logical line. Byte counts, line numbers, and absolute decoded columns continue across chunks, CRLF, and a final unterminated line.

Provider shapes, JWT, credential URLs, assignment, and contextual entropy reuse the established detectors on overlapping windows. Overlap is larger than the bounded token and URL patterns; already committed match endings prevent duplicates. Whole-line hash/documentation context is tracked as bounded state. The existing AWS ID/nearby assignment severity relation uses raw-free candidate line numbers. Private-key BEGIN/END state persists across segments and lines while its body is discarded. If unbounded assignment whitespace exceeds the provable overlap context, or a match/finding budget prevents complete analysis, `SECRET_LARGE_TEXT_INCOMPLETE` marks the file `PARTIAL`; it is never silently counted as complete. Small-file detector and fingerprint inputs are unchanged. No raw chunk, long line, private-key body, or matched value enters a Finding or report.

## Known limits

The JS/TS source-literal reader is bounded lexical analysis, not a complete language parser. Complex multiline expressions, nested interpolation, unusual escaping, and indirect dataflow may remain outside generic detection. Typed environment parameters are declaration evidence rather than runtime trust guarantees. A custom token helper is neither assumed secure nor labeled hardcoded without literal evidence. Test-fixture classification remains heuristic; provider-specific patterns are independent. `COMPLETE` continues to mean completion within enabled, supported analyzers, not coverage of every vulnerability class.

Provider formats are conservative subsets and can change independently of this offline rule set. The scanner cannot establish validity, ownership, exposure history, or exploitability. Generic line rules may miss multiline assignments, unusual quoting/encodings, and secrets without context. Generated-call recognition does not claim arbitrary helpers are secure; a large-text streaming file lacks the small-file AST proof and remains conservative. Test-fixture classification may miss other synthetic values or suppress a similarly named generic value in a test; provider-specific matches are unaffected. A private-key BEGIN marker can report an incomplete or synthetic block. Target-controlled filenames are root-relative and matched-value occurrences are redacted; reporters still need display escaping and broader secret checks. If two redacted paths collide at the same anchor, the scanner assigns distinct safe fingerprints using file identity (or deterministic artifact order) and marks coverage partial; these collision identities may change if files are recreated. The path-based reopen is not a race-free Windows sandbox; UNC/junction/long-path behavior remains unverified on this host. No network requests, third-party secret tools, AI, SAST, or active credential validation are used.
