# Remediation and patch proposals

Phase 8 adds optional guidance and **proposal-only** single-file edits. `--propose-fixes` runs the planner after the deterministic scan. `--ai-remediation` is an additional, separate Gemini grant; `--ai` review alone never requests a patch. `--offline` permits local guidance and deterministic proposals, while disabling Gemini patch egress. No CLI apply/write/fix option exists. Every proposal says `human_approval_required=true`; applying, testing, building, installing, or executing target code is outside this phase.

## Strategy and scope

- `GUIDANCE_ONLY` covers secrets, dependency advisories, injection findings without unambiguous edits, unsafe deserialization, dynamic execution, and behavior signals. Secret advice includes removal, trusted runtime injection, rotation/revocation if real, history review, and access-log review. The tool performs none of those external actions. Dependency proposals list provider-reported fixed versions as review input without inferring a minimum or editing manifests and lockfiles.
- `DETERMINISTIC` currently proposes one narrow rule: a Python TLS call with an exact `verify=False` AST literal can change that literal to `verify=True`. No whole-file formatter, new import, or dependency is used. Ambiguous source remains guidance.
- `AI_ASSISTED` uses Gemini 3.8 Flash with medium thinking by default through the Phase 6 provider adapter. It sends a bounded redacted window around a non-secret Python SAST finding, with no Gemini tools, storage, search, URL context, code execution, computer use, or function calling. A structured response supplies line replacements. The tool generates the unified diff itself. Target comments are hostile data, and AI text has no authority to widen file/range scope or approve its own patch. No live Gemini request is part of Phase 8 tests.

The planner processes primary findings in bounded priority order, at most 50 proposals and 20 patches by default. Supporting behavior signals do not generate duplicate patches. One patch changes one Phase 1 admitted, regular, non-reparse, root-contained, UTF-8 Python source file at the finding path. `.git`, `.env*`, private-key material, scanner config, agent/status/handoff files, and workflow files are forbidden targets. Unknown encoding and unsupported languages receive guidance only. Admitted content is reopened through the bounded Phase 1 reader; identity, size, mtime, and optional discovery hash must still match. A stale file causes `PATCH_SOURCE_STALE` and should be rescanned.

## Validation

Line edits are checked for overlap, range, distance from the finding, size, changed-line and hunk budgets. The tool applies edits **only in memory**, preserving supported UTF-8/BOM and LF/CRLF form. Python is checked with bounded `ast.parse`, never imported or executed. The existing bounded Python taint engine scans original and proposed text in memory. The target rule must be present before, reduced after, and no new supported HIGH/CRITICAL finding may appear. New lower-severity findings make validation partial. Suppression comments, obvious dangerous APIs, new endpoints, deletion/comment-out of code, missing declarations, and credential-bearing changed lines are rejected conservatively. These are heuristics; they do not prove functional correctness.

`VALIDATED_STATICALLY` means the edit applies, syntax parses, the supported target finding disappears, and no supported new static finding appears. `PARTIAL_VALIDATION` records assumptions or a new lower-severity finding. `REJECTED` candidates are not published as patches. **Runtime tests: NOT_RUN** in every case. Static finding disappearance never means the application works or that a vulnerability is conclusively fixed.

## Privacy and reporting

Patch engine source and AI responses are transient memory only. A public `PatchCandidate` has relative path, content hashes, provenance, bounded diff, and validation metadata, never full original/proposed source or a raw secret. The unified diff uses zero context lines and is re-redacted at report serialization. A changed line with a recognized secret is rejected rather than exposed; heuristic redaction may miss novel forms. There is no `.patch` export. Console omits diffs by default and shows a short public diff only in verbose mode. JSON 1.1 adds `remediation_proposals`; HTML escapes and collapses proposals and public diffs. SARIF fixes are intentionally deferred to avoid suggesting an automatically applicable fix.

Diagnostics are fixed codes such as `PATCH_SOURCE_STALE`, `PATCH_SCOPE_VIOLATION`, `PATCH_FORBIDDEN_TARGET`, `PATCH_TOO_LARGE`, `PATCH_SYNTAX_INVALID`, `PATCH_NEW_HIGH_FINDING`, `PATCH_SECURITY_SUPPRESSION_DETECTED`, `PATCH_DESTRUCTIVE_CHANGE`, `PATCH_SECRET_EXPOSURE`, `PATCH_AI_UNAVAILABLE`, and `PATCH_AI_RESPONSE_INVALID`. No SDK exception, source, key, or raw prompt enters them. AI patch requests are sequential, capped independently at three by default, and have bounded context, output, token estimate, and time. Provider correctness and heuristic redaction remain residual risks.
