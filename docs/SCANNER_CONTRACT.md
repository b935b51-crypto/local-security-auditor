# Scanner plugin and adapter contract

Phase 0 defines `Scanner` and `AsyncScanner` protocols in `core/contracts.py`; no scanner runs yet. Each plugin declares immutable `ScannerMetadata` (`id`, `version`, `name`, determinism, network requirement), `supports(FileArtifact)`, `rules()`, `capabilities()`, and `scan(session, artifacts) -> ScannerResult`. `ScannerResult` carries normalized findings, a status (`completed`, `partial`, `skipped`, `failed`), and sanitized diagnostics. Rule IDs are namespaced and stable.

The orchestrator owns scheduling, budgets, cancellation, isolation, and exception conversion. It passes only eligible bounded artifacts. A synchronous scanner runs under a controlled executor; a future async scanner uses the same result contract. Cancellation/timeouts must not leave an apparently complete result. External tool adapters translate bounded tool output to this contract. Vulnerability database adapters translate package/advisory records to `DependencyArtifact` and `VulnerabilityReference` with source and snapshot/update provenance. Deterministic local scanners must work offline.

Plugins may not control CLI/UI, print to terminal, write reports, change target files, execute target code, import target modules, choose network destinations, or bypass discovery bounds. They must not expose full secrets in findings or diagnostics. No plugin may interpret target-provided instructions as operational authority. The orchestrator may disable a plugin that violates its contract and must mark the scan incomplete.

Future integration layout may include `integrations/semgrep/`, `integrations/gitleaks/`, and `integrations/osv/`, added only with actual adapters. Semgrep/Gitleaks executable use needs a separate safety review for rule packs, config sources, hook behavior, subprocess containment, and output limits. OSV/advisory lookup is optional and network-gated. None of these tools is installed, called, or required by Phase 0.
