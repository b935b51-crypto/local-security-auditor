# Reporting contract — schema 1.1

Phase 8 adds optional `remediation_proposals` and `summary.remediation` to the canonical report, advancing JSON from 1.0 to 1.1. The historical [1.0 schema](report-schema-v1.json) remains; the current compact [1.1 schema](report-schema-v1.1.json) includes proposal structure. Each proposal is a redacted public view with approval required and runtime tests `NOT_RUN`. Internal source and raw AI patch output are never serialized. Console shows counts and status, with a short diff only in verbose mode; HTML escapes a collapsed public diff. SARIF fixes are intentionally deferred. See [Remediation](REMEDIATION.md).

The orchestrator builds one immutable `ScanReport` from Phase 1 discovery, Phase 2–4 scanner results, Phase 5 correlation/risk, and optional Phase 6 AI annotations. All four renderers consume this object. They never reopen target files, rerun scanners, alter findings, or reconstruct secrets. `reporting/serialization.py` is an explicit public-field whitelist; it deliberately excludes raw evidence snippets, source files, raw provider payloads, API keys, and internal metadata. Output text is redacted again, paths are root-relative, terminal controls are rendered inert, and HTML escapes every value. Novel secret formats may evade heuristic text redaction; scanner-side raw-free Findings remain essential.

Canonical JSON is UTF-8, valid JSON (`allow_nan=False`), and has stable keys and ordering for a given `ScanReport`; scan ID, timestamps, and duration vary between scans. `schema_version` (`1.1`) is independent of the tool version. The major sections are `tool`, `scan`, `environment`, `coverage`, `discovery`, `scanners`, `summary`, `diagnostics`, `rules`, `findings`, `finding_groups`, `attack_paths`, `risk_assessments`, `ai_reviews`, `remediation_proposals`, `report_truncated`, and `limitations`. The compact current structural schema is [1.1](report-schema-v1.1.json).

Coverage is first-class. `COMPLETE` means current deterministic components finished within their declared scope; it is **not** a proof of safety. `PARTIAL` means skipped/unsupported/unavailable data, a scanner failure, or truncated report; `ABORTED` means a budget/deadline stopped work; `FAILED` means discovery could not start. Optional AI `DISABLED` does not make deterministic coverage partial. Quick profile shows SAST and correlation as `DISABLED`. Every report includes component statuses, fixed-code reasons, skipped counts, budget hits, and AI eligible/reviewed counts. Zero findings is worded **“No findings detected in the analyzed coverage.”** Offline exact versions without advisory data remain `NO_DATA`, never a clean vulnerability result.

The console shows coverage at the top, severity and priority counts, up to 20 primary findings, supporting-signal counts, attack candidates, AI advisory status, dependency data, and warnings. Behavior signals remain distinct from vulnerability claims. No source excerpt is dumped by default. `--verbose` only reveals sanitized fixed diagnostics. JSON is the complete machine-facing representation, subject to explicit report caps.

SARIF is version `2.1.0`. Rules are deduplicated; results represent deterministic findings only, with relative URI locations and safe fingerprints. CRITICAL/HIGH map to `error`, MEDIUM to `warning`, LOW/INFO to `note`. AI verdicts may appear as advisory result properties and never create new authoritative results or change severity. Coverage and truncation live in `run.properties`. Source-to-sink `codeFlows` are deferred; no source is reopened to construct them. Structural tests validate the produced subset; the full official schema has not been used as a validator locally.

HTML is a single static file with embedded CSS, no JavaScript, no remote assets, and a restrictive CSP (`default-src 'none'`). Its default locale is Traditional Chinese (`zh-TW`); tool-owned display text is centralized in `reporting/i18n.py`. Machine codes, IDs, paths, package names, and untrusted finding/AI/source text are not translated. It escapes filenames, findings, provider/AI text, diagnostics, and links. It contains summary, findings, groups, potential attack paths, dependency summary, AI advisories, coverage, and privacy disclosure. It does not embed source files or raw secret previews. Console, JSON 1.1, and SARIF 2.1.0 contracts retain their existing language and field names.

The 1.0.0 wheel includes `reporting/i18n.py` and all reporting modules. JSON/SARIF schemas in `docs/` are reference documents; runtime validation and format versions are implemented in packaged Python code and do not read repository-relative schema files. A clean wheel install produced JSON 1.1, zh-TW HTML, and SARIF 2.1.0 from a synthetic offline target; see [release notes](../RELEASE_NOTES.md) and historical [Release Candidate](RELEASE_CANDIDATE.md).

SAST and behavior JSON scanner summaries add `artifacts_considered`, `artifacts_applicable`, and `artifacts_not_applicable` without changing schema version 1.1; `artifacts_skipped` now means applicable artifacts not analyzed. Non-applicable files do not reduce completeness. AST node/depth diagnostics keep stable machine codes and root-relative paths; HTML supplies zh-TW descriptions for those codes.

Report caps: 1,000 rendered findings, 300 diagnostics, 1,000 groups, 100 attack paths, 1,000 risk assessments, 100 AI reviews, and 8 MiB HTML. Totals and `report_truncated=true` disclose truncation. A report exceeding the HTML byte cap fails output rather than silently dropping sections. Reports are written via a same-directory temporary file, flush/fsync, and atomic link/replace. Existing output requires `--force`; parent and final paths reject symlinks/reparse points, special files, device/UNC forms and Windows reserved names. Filesystem races and unusual remote filesystems remain residual risks; output on an operator-selected path is an explicit operator write.

## Project scope visibility (v1 RC hardening)

JSON 1.1 adds `discovery.scope` without changing or removing existing fields. It contains intentional excluded directory/file totals, default/user policy totals, a bounded list of root-relative entries with class and reason codes, and `entries_omitted` when more than 200 exclusions occurred. `discovery.skipped_files` and `coverage.skipped_files` continue to mean failed or incomplete file analysis; exclusions are separate and do not by themselves reduce completeness. The console shows exclusion totals; SARIF `run.properties.scanScope` carries the same additive data. Machine codes and field names remain stable.

Hardening #5 adds optional, backward-compatible integer fields `summary.dependency.first_party_roots` and `summary.dependency.unresolved_third_party` to JSON 1.1. Gate 1.0 accepts older reports without them and validates their counts when present; its coverage policy is unchanged. zh-TW HTML displays both counts. `SECRET_FILE_TOO_LARGE` now carries a redacted target-relative diagnostic path into JSON and HTML. No report renderer reads an oversized file to produce that path, and an oversized file still makes coverage `PARTIAL`.

Hardening #6 additively exposes `batch_requests_used/limit`, `detail_requests_used/limit`, `total_requests_used/limit`, `deduplicated_advisories`, and `provider_budget_reached` under `summary.dependency` in JSON 1.1. Existing `queries` remains the number of exact package keys submitted, not the number of HTTP requests. zh-TW HTML and console show request usage. On budget exhaustion, HTML warns that obtained advisories are retained and unqueried dependencies are not interpreted as vulnerability-free. Machine diagnostic codes remain stable and raw OSV payloads are never rendered.

Hardening #7 additively exposes `advisories_seen`, `advisories_accepted`, `advisories_truncated`, `advisory_limit`, and `advisory_limit_reached` under `summary.dependency`. These count advisory **references**, not confirmed vulnerable packages or Findings. `seen` and `accepted` count stable unique IDs per package result; `truncated = seen - accepted`. The per-result and per-batch processing cap stays 100. A truncated lookup is incomplete and cannot be reported or cached as a complete `NO_MATCH`. JSON and console retain fixed machine wording; zh-TW HTML shows an escaped safety warning and the three counts, separately from the detail-request budget. No raw OSV response is included.

HTML (`zh-TW`) shows the scope summary and at most 20 exclusion paths with escaped text. It hides singleton finding groups with no supporting signal or attack-path relevance; JSON group data remains complete. A visible group names its primary finding and relative location instead of displaying a raw fingerprint. Existing CSP, no-script/no-remote-assets, redaction, and escaping rules still apply. A scan can be `COMPLETE` only within its explicitly declared scope; cache/environment exclusions do not prove those trees safe.

Hardening #8 additively exposes `scanners[id=secrets].large_text` in JSON 1.1: the active `FULL_BUFFER`/`LARGE_TEXT_BOUNDED` modes, scanned and incomplete large-text file counts, bytes, segmented long lines, and incomplete long lines. Console and zh-TW HTML show bounded large-text coverage without source content. `SECRET_LARGE_TEXT_INCOMPLETE` is a fixed diagnostic with a redacted relative path; incomplete long-line rule context remains `PARTIAL`. A completed large-text file can coexist with other incomplete Secret artifacts, so the HTML message uses the large-text partial count rather than the whole scanner's status. The Gate continues to use canonical component coverage and unchanged policy 1.0.

## Finding identity and provenance hardening (1.0.3 source; no version bump)

The report collapses only Findings with the same fingerprint **and** detector, rule, category, full location, source/sink, severity/confidence, CWE, structured evidence class, and dependency/advisory identity. A fingerprint reused for differing semantics remains a visible collision diagnostic and incomplete report coverage; distinct rule or sink signals are not silently removed. Direct `exec(compile(...))` / `eval(compile(...))` emits one dynamic-code capability signal at the outer operation. Standalone `compile()` remains visible. Remediation planning consumes final primary Findings, so an exact duplicate cannot create two equivalent proposal cards.

`finding_groups` now connects a specific command behavior signal to a generic process signal only when the operation shares file, line, and column. The specific signal is PRIMARY, the generic one SUPPORTING. JSON/SARIF retain both results and their stable fingerprints/roles; the existing severity and total counts still count both distinct machine Findings. Console lists primary issues, while HTML collapses supporting details. An additive `context:test_code` tag is derived from bounded relative path shape (`test/`, `tests/`, `.test.`, `.spec.`); it never suppresses or downgrades a Finding. A dynamic-code `context:stored_source_lookup` tag requires a local AST lookup from a `dict(self.sources)` binding. It proves that syntactic lookup only: upstream trust, absence of remote input, and sandboxing are **not** established.

`summary.dependency` additively reports `provider`, assessed/unassessed exact **records**, fresh/stale accepted cache **lookup keys**, cache age range in seconds when known, and cache TTL. Existing `exact_versions`, `queries`, `cache_hits`, `matches`, and network request counters keep their meanings. Stale offline entries remain incomplete and are unassessed for freshness. A zero match is worded “No known vulnerability matches in assessed dependency coverage,” never “no dependency vulnerabilities.” OSV cache is normalized per-query data, not a database snapshot. The report does not expose a cache directory or raw provider payload.

When AI review is requested but the deterministic selector has no eligible items, `summary.ai_status` is `no_eligible_items` with zero requests, distinct from `disabled` and `complete`. The existing coverage component vocabulary represents this not-applicable AI state as `DISABLED`; deterministic overall coverage and Gate policy are unchanged. `PATCH_AI_UNAVAILABLE` remains remediation availability, separate from Finding AI review. HTML presents the no-eligible state in zh-TW, without implying Gemini reviewed anything.
