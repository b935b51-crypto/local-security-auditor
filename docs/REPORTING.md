# Reporting contract — schema 1.1

Phase 8 adds optional `remediation_proposals` and `summary.remediation` to the canonical report, advancing JSON from 1.0 to 1.1. The historical [1.0 schema](report-schema-v1.json) remains; the current compact [1.1 schema](report-schema-v1.1.json) includes proposal structure. Each proposal is a redacted public view with approval required and runtime tests `NOT_RUN`. Internal source and raw AI patch output are never serialized. Console shows counts and status, with a short diff only in verbose mode; HTML escapes a collapsed public diff. SARIF fixes are intentionally deferred. See [Remediation](REMEDIATION.md).

The orchestrator builds one immutable `ScanReport` from Phase 1 discovery, Phase 2–4 scanner results, Phase 5 correlation/risk, and optional Phase 6 AI annotations. All four renderers consume this object. They never reopen target files, rerun scanners, alter findings, or reconstruct secrets. `reporting/serialization.py` is an explicit public-field whitelist; it deliberately excludes raw evidence snippets, source files, raw provider payloads, API keys, and internal metadata. Output text is redacted again, paths are root-relative, terminal controls are rendered inert, and HTML escapes every value. Novel secret formats may evade heuristic text redaction; scanner-side raw-free Findings remain essential.

Canonical JSON is UTF-8, valid JSON (`allow_nan=False`), and has stable keys and ordering for a given `ScanReport`; scan ID, timestamps, and duration vary between scans. `schema_version` (`1.1`) is independent of the tool version. The major sections are `tool`, `scan`, `environment`, `coverage`, `discovery`, `scanners`, `summary`, `diagnostics`, `rules`, `findings`, `finding_groups`, `attack_paths`, `risk_assessments`, `ai_reviews`, `remediation_proposals`, `report_truncated`, and `limitations`. The compact current structural schema is [1.1](report-schema-v1.1.json).

Coverage is first-class. `COMPLETE` means current deterministic components finished within their declared scope; it is **not** a proof of safety. `PARTIAL` means skipped/unsupported/unavailable data, a scanner failure, or truncated report; `ABORTED` means a budget/deadline stopped work; `FAILED` means discovery could not start. Optional AI `DISABLED` does not make deterministic coverage partial. Quick profile shows SAST and correlation as `DISABLED`. Every report includes component statuses, fixed-code reasons, skipped counts, budget hits, and AI eligible/reviewed counts. Zero findings is worded **“No findings detected in the analyzed coverage.”** Offline exact versions without advisory data remain `NO_DATA`, never a clean vulnerability result.

The console shows coverage at the top, severity and priority counts, up to 20 primary findings, supporting-signal counts, attack candidates, AI advisory status, dependency data, and warnings. Behavior signals remain distinct from vulnerability claims. No source excerpt is dumped by default. `--verbose` only reveals sanitized fixed diagnostics. JSON is the complete machine-facing representation, subject to explicit report caps.

SARIF is version `2.1.0`. Rules are deduplicated; results represent deterministic findings only, with relative URI locations and safe fingerprints. CRITICAL/HIGH map to `error`, MEDIUM to `warning`, LOW/INFO to `note`. AI verdicts may appear as advisory result properties and never create new authoritative results or change severity. Coverage and truncation live in `run.properties`. Source-to-sink `codeFlows` are deferred; no source is reopened to construct them. Structural tests validate the produced subset; the full official schema has not been used as a validator locally.

HTML is a single static file with embedded CSS, no JavaScript, no remote assets, and a restrictive CSP (`default-src 'none'`). Its default locale is Traditional Chinese (`zh-TW`); tool-owned display text is centralized in `reporting/i18n.py`. Machine codes, IDs, paths, package names, and untrusted finding/AI/source text are not translated. It escapes filenames, findings, provider/AI text, diagnostics, and links. It contains summary, findings, groups, potential attack paths, dependency summary, AI advisories, coverage, and privacy disclosure. It does not embed source files or raw secret previews. Console, JSON 1.1, and SARIF 2.1.0 contracts retain their existing language and field names.

The 0.9.0 wheel includes `reporting/i18n.py` and all reporting modules. JSON/SARIF schemas in `docs/` are reference documents; runtime validation and format versions are implemented in packaged Python code and do not read repository-relative schema files. A clean wheel install produced JSON 1.1, zh-TW HTML, and SARIF 2.1.0 from a synthetic offline target; see [Release Candidate](RELEASE_CANDIDATE.md).

SAST and behavior JSON scanner summaries add `artifacts_considered`, `artifacts_applicable`, and `artifacts_not_applicable` without changing schema version 1.1; `artifacts_skipped` now means applicable artifacts not analyzed. Non-applicable files do not reduce completeness. AST node/depth diagnostics keep stable machine codes and root-relative paths; HTML supplies zh-TW descriptions for those codes.

Report caps: 1,000 rendered findings, 300 diagnostics, 1,000 groups, 100 attack paths, 1,000 risk assessments, 100 AI reviews, and 8 MiB HTML. Totals and `report_truncated=true` disclose truncation. A report exceeding the HTML byte cap fails output rather than silently dropping sections. Reports are written via a same-directory temporary file, flush/fsync, and atomic link/replace. Existing output requires `--force`; parent and final paths reject symlinks/reparse points, special files, device/UNC forms and Windows reserved names. Filesystem races and unusual remote filesystems remain residual risks; output on an operator-selected path is an explicit operator write.
